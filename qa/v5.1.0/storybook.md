# Storybook: Component Playground and Embeds

The component Storybook at [story.uxp.iviva.com](https://story.uxp.iviva.com) is rebuilt. Each uxp component has one playground page. The gitbook component pages link to it.

| | |
|---|---|
| **Where:** | [story.uxp.iviva.com](https://story.uxp.iviva.com), and the playground links in the Live preview section of each component page in the uxp documentation. |
| **Issue:** | Most component previews were empty or showed an error, because the stories started with blank values. The sidebar had components outside any group. Callbacks such as `onClick` could not be tried. The documentation site never showed the embedded previews, because GitBook removes embedded frames. Props could not be passed in an embed link. |
| **What changed:** | 128 components have a playground page. Advanced components have none. The pages are grouped by purpose: Buttons, Charts, Dashboard, Data Display, Feedback, Forms, Inputs, Layout, Loaders, Navigation, Overlays and Utilities. Each page starts with working sample values. The **Properties** panel changes the preview straight away. The **Code** tab shows the matching code. The **Data** tab edits array and object props as JSON. |
| **Callbacks and code props:** | Callbacks and props that take code (render functions, `children`) show a picker of sample code and the code itself. For example, a button's `onClick` offers a sync and an async handler. Picking the async one makes the button show its loading state when clicked. Render overrides start as "None", so the component looks as it does by default. |
| **Themes:** | The **Component theme** menu switches between the four built-in themes: Light, Dark, Glass Light and Glass Dark. The preview uses the themes' real default values and background, the same as in the app. |
| **Embed links:** | **Copy embed link** copies a link that shows only the preview, with the props and theme currently set. Links can also be written by hand. See [Tooling](../../uxp/tooling.md) for the `args`, `props` and `globals` parameters. An embed shows an **Open in playground** link. |
| **Helpers and advanced components:** | A component that is mostly used through another one, such as ObjectDetailsPanelHeader, sits in the main component's group, after it. Its page says "Part of …". Components only needed to build custom components (for example PortalContainer and DashboardConfigPanel) have no playground page. Their documentation page says "Advanced". All loaders are in one **Loaders** group. The DataEntry components and SlideInForm are in **Forms/Dynamic Form**. |
| **Preview:** | The component shows on the theme's own page colour, or the gradient for glass themes, with no white box around it. It never scrolls. A component larger than the preview (for example RadialGauge) is scaled down so all of it shows, including legends and labels. Charts no longer jitter. Modals, dropdowns and tooltips open inside the preview, and the Properties panel stays usable. |
| **Deprecated:** | LinkButtonWidget and LinkWidgetContainer show a red "Deprecated" notice on the playground and on the documentation page. |
| **Removed:** | PinnedItemsButton is no longer exported from `uxp/components`. Nothing used it. |
| **Docs live previews:** | Each component page in the uxp documentation has a **Live preview** section after the examples. It has a link to the component's playground page. Under **Variants** there is one link per example that renders the component. Each link opens the playground with that example's props, for example ButtonComponent's "Icon only button". |
| **Sample data:** | Components that normally load data from iviva (user details, dashboards, media library, user groups, app roles, localisation messages) show fixed sample data. Nothing is saved. Uploads and deletes do not reach a server. |
| **Worth checking:** | Open several components from each group: the preview shows content and no error, and never scrolls. Open RadialGauge and a chart with its legend on: all of it shows and nothing jitters. Open Modal: it stays inside the preview. Change a prop and check the preview follows, including a table's page size. Pick another callback sample and use the component. Switch each theme and check colours and background. Copy an embed link after changing props and theme, and open it in a new tab: it shows the same preview. Open a component page in the uxp documentation and check its playground links open the component with the example's props. |
