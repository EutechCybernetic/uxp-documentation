# Pages & Dashboards

A page can be code you wrote, a dashboard an administrator composed, or a mix of the two. This section
covers the four shapes and the surfaces other apps can extend.

| Page | What is in it |
|---|---|
| [Building Pages & Dashboards](./building-pages.md) | The four ways to put a page in front of a user, how to pick between them, and what a page receives as props |
| [Embedded Dashboard](./embedded-dashboard.md) | Put a configurable widget dashboard inside a view: default layouts, edit mode, per-group layouts, breakpoints, filters and background surfaces |
| [Dashboard Page Walkthrough](./dashboard-page-walkthrough.md) | A complete analytics page end to end: widgets, drill-downs in the URL, scoped filters and a shipped layout |
| [Pluggable Views](./pluggable-views.md) | Let an account replace a page an app ships, instead of forking it |
| [Injected Detail Tabs](./injected-tabs.md) | Contribute a tab to another app's object details page, and accept tabs in your own |
| [External Components](./external-components.md) | Reuse the System app's shared components: activity log, attachments, documents, images and role configurators |

## Start here

If you are unsure which shape a screen should be, read
[Building Pages & Dashboards](./building-pages.md) first: it is the decision, and the rest of this
section is the detail behind each option.
